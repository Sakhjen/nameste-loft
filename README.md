# На месте

Локальный сайт и админка ивент-пространства. Нужен Node.js 24 или новее. Устанавливать зависимости не требуется.

```sh
npm start
```

Откройте [афишу](http://127.0.0.1:4173/) или [админку](http://127.0.0.1:4173/admin).

| Локальный логин | Пароль для демонстрации |
| --- | --- |
| `owner` | `meste-owner-demo` |
| `partner` | `meste-partner-demo` |

У аккаунтов одинаковые права. База SQLite создаётся в `data/site.sqlite`. При первом локальном запуске в новой базе появляются 12 демонстрационных событий на декабрь 2026 года и опрос на январь 2027 года. Время событий на сайте и в админке указано по Москве.

## Работа с админкой

- **Расписание**. Создавайте события, редактируйте дату, цену, зал и описание. Флажок «Показать в афише» публикует событие. Снятие флажка возвращает его в черновики и закрывает приём новых заявок.
- **Голосования**. Создайте опрос на выбранный месяц и добавьте варианты. Админка показывает результаты во время опроса. Закройте текущий опрос, чтобы открыть новый. Посетитель может изменить голос до закрытия, если использует тот же браузер с сохранёнными cookies.
- **Заявки**. Откройте запись на событие или предложение организатора. Свяжитесь с человеком по контакту в заявке и обновите её статус. В разделе «Заявки» фильтры по типу и статусу.

## Настройки для этапа хостинга

Для публичного запуска нужны HTTPS, отдельные пароли и постоянный каталог для SQLite. В режиме `NODE_ENV=production` сервер требует `APP_ORIGIN` с HTTPS и два разных пароля в `OWNER_PASSWORD` и `PARTNER_PASSWORD`. `APP_ORIGIN` задаётся без завершающего слеша. `HOST`, `PORT`, `DATA_DIR` и `VENUE_ADDRESS` задают интерфейс, порт, каталог базы и адрес пространства. На новой базе демо-данные в режиме production отключены по умолчанию. Локально их можно отключить при первом запуске новой базы через `SEED_DEMO=0`.

Для Caddy, который принимает публичные запросы напрямую и проксирует их на `127.0.0.1`, используйте `HOST=127.0.0.1` и `TRUST_LOCAL_PROXY=1`. Тогда сервер использует адрес посетителя для ограничения частоты запросов.

## Обновление на VPS

Отправьте локальные коммиты в ветку `main` командой `git push`. Затем запустите на VPS:

```sh
na-meste-update
```

Команда подтягивает актуальную версию из GitHub, перезапускает службу `na-meste` и проверяет ответ приложения. Если новая версия не запускается, команда возвращает предыдущий коммит. База хранится в `/var/lib/na-meste`, а настройки и пароли — в `/etc/na-meste.env`.
